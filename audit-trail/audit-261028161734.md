## 1. Panduan Membuka Akses ke Jaringan Kabel (LAN) secara Aman

Aplikasi WilkerStat Checker saat ini berjalan dengan WSGI Server **Waitress** pada konfigurasi `HOST = 0.0.0.0` dan `PORT = 11750`. Artinya, server aplikasi sudah otomatis mendengarkan seluruh antarmuka jaringan (Ethernet / LAN).

### A. Langkah Akses Petugas dari Komputer Lain
1. Cari IP lokal komputer host pada jaringan kabel melalui terminal host (`ipconfig` $\rightarrow$ periksa IPv4 pada Ethernet Adapter, misalnya `192.168.1.50`).
2. Petugas di komputer lain pada switch/kabel yang sama cukup membuka browser dan mengakses:
   ```text
   http://192.168.1.50:11750
   ```
   *Petugas TIDAK perlu mengakses file explorer PC ini, tidak perlu sharing folder, dan tidak perlu remote desktop.*

### B. Pengamanan Sistem (Hardening)
1. **Tanpa File Sharing**: Pastikan fitur *File and Printer Sharing* (SMB port 445/139) dan *Remote Desktop (RDP)* tetap dinonaktifkan pada profil jaringan. Interaksi petugas 100% hanya melalui HTTP web browser.
2. **Windows Defender Firewall (Inbound Rule Terbatas)**:
   - Buat satu aturan masuk (*Inbound Rule*) khusus protokol **TCP**, port **11750**.
   - Setel profil hanya aktif pada **Private Network** (bukan Public).
   - (*Opsional/Rekomendasi*): Pada tab *Scope*, batasi *Remote IP Addresses* hanya ke subnet kantor lokal (misal `192.168.1.0/24`).
3. **Keamanan Waitress**:
   - Waitress adalah WSGI production server murni (bukan development server Werkzeug dengan debugger aktif), sehingga tidak rentan eksekusi remote code.
   - Batasan ukuran upload sudah dikunci melalui `MAX_CONTENT_LENGTH = 200MB` di `config.py`.
4. **Isolasi Master Data**: Mengaktifkan `DEV=false` agar petugas di LAN tidak bisa merusak konfigurasi target maupun menghapus data master.

## 2. Logika Pengunggahan Titik Bangunan: Mekanisme & Key Unik

### A. Apakah Upload Sebagian akan Menimpa/Menghapus Titik Lain?
**Tidak.** Sistem menggunakan prinsip **UPSERT selektif** (*Insert or Update*).
- Upload titik parsial oleh Petugas A **tidak akan menghapus** titik milik Petugas B atau titik di SLS lain yang sudah tersimpan di database.
- Baris titik di luar file yang diunggah tetap utuh di database.

### B. Kunci Unik (*Primary Key*) Pencegah Salah Timpa
- Kunci integritas unik adalah kolom **`assignment_id`** (Kode unik penugasan/tagging per-keluarga).
- Alur kerja di [validate_dot.py](file:///c:/laragon/www/wilkerstat-checker/validate_dot.py):
  1. Sistem melakukan pengecekan:
     ```sql
     SELECT geom_hash, flag_repair, flag_position, status FROM dot WHERE assignment_id=?
     ```
  2. **Jika `assignment_id` sudah ada**:
     - Bila koordinat dan atribut tidak berubah $\rightarrow$ dilewati (`unchanged_count + 1`).
     - Bila ada pergeseran/perubahan koordinat $\rightarrow$ baris tersebut di-update (`UPDATE dot ... WHERE assignment_id=?`).
  3. **Jika `assignment_id` belum ada**:
     - Di-insert sebagai baris baru (`INSERT INTO dot ...`).

## 3. Logika Pengunggahan Poligon SLS: Mekanisme & Key Unik

### A. Apakah Upload Sebagian akan Menimpa/Menghapus Poligon Lain?
**Tidak.** Serupa dengan titik, pengunggahan poligon SLS juga menggunakan prinsip **UPSERT selektif**.
- Petugas yang mengunggah 1 desa atau beberapa SLS tidak akan menghapus poligon SLS lain yang sudah diunggah oleh petugas sebelumnya.
- Seluruh poligon yang ada di database dipertahankan.

### B. Kunci Unik (*Primary Key*) Pencegah Salah Timpa
- Kunci integritas unik adalah kolom **`idsubsls`** (Kode 16 digit wilayah Sub-SLS: `kdprov + kdkab + kdkec + kddesa + kdsls + kdsubsls`).
- Alur kerja di [validate_shape.py](file:///c:/laragon/www/wilkerstat-checker/validate_shape.py):
  1. Sistem melakukan pengecekan:
     ```sql
     SELECT geom_hash, attrs FROM shape WHERE idsubsls=?
     ```
  2. **Jika `idsubsls` sudah ada**:
     - Bila poligon dan atribut identik $\rightarrow$ dilewati (`unchanged_count + 1`).
     - Bila poligon mengalami revisi batas/perbaikan geometri $\rightarrow$ di-update (`UPDATE shape ... WHERE idsubsls=?`).
  3. **Jika `idsubsls` belum ada**:
     - Di-insert sebagai poligon baru (`INSERT INTO shape ...`).

## 4. Perancangan Fitur `DEV=true/false` di Lingkungan `.env`

### A. Konsep & Perilaku
| Mode | `DEV=true` (Default / Development) | `DEV=false` (Production / Lapangan) |
|---|---|---|
| **UI Upload (`/upload`)** | Menampilkan 3 kartu: Master Poligon, Titik Bangunan, Shape Poligon | **Menyembunyikan** kartu Master Poligon. Petugas hanya melihat Titik Bangunan & Shape Poligon |
| **Endpoint Upload Master (`POST /api/upload`)** | Berfungsi normal memproses file master | **Diblokir** (HTTP 403 Forbidden: "Upload master poligon dinonaktifkan dalam mode produksi") |
| **Endpoint Reset Data (`POST /api/admin/reset-data`)** | Berfungsi normal untuk admin | **Dibatasi** agar target `master` dan `all` tidak bisa dieksekusi dari antarmuka luar |

### B. Langkah Implementasi Kode

1. **Konfigurasi di [.env](file:///c:/laragon/www/wilkerstat-checker/.env) & [config.py](file:///c:/laragon/www/wilkerstat-checker/config.py)**:
   ```python
   DEV = _env_bool("DEV", default=True)
   ```

2. **Proteksi Backend di [app.py](file:///c:/laragon/www/wilkerstat-checker/app.py)**:
   ```python
   # Di endpoint /upload (render template)
   @app.route("/upload")
   def upload_page():
       return render_template("upload.html", dev=config.DEV)

   # Di endpoint /api/upload
   if upload_type == "master_shape" and not config.DEV:
       conn.close()
       return jsonify({"error": "Upload master poligon dinonaktifkan dalam mode operasional."}), 403
   ```

3. **Proteksi Tampilan di [templates/upload.html](file:///c:/laragon/www/wilkerstat-checker/templates/upload.html)**:
   ```jinja2
   <div class="upload-grid">
       {% if dev %}
       <!-- Master Shape Card -->
       <div class="upload-card">
           <h3>Master Poligon</h3>
           ...
       </div>
       {% endif %}

       <!-- Titik Bangunan Card -->
       <div class="upload-card">...</div>

       <!-- Shape Card -->
       <div class="upload-card">...</div>
   </div>
   ```
