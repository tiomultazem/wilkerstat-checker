# Analisis & Pencanangan: Perbaikan Tampilan Gap/Overlap & Komparasi Toleransi QGIS

## 1. Pencanangan Perbaikan Tampilan Gap & Overlap Bernilai 0 di Capaian

### A. Masalah
Di [static/home.js](file:///c:/laragon/www/wilkerstat-checker/static/home.js) (baris 97–98):
```javascript
: mode === 'gap' ? (s.gap_count || 0)
: (s.overlap_count || 0);
```
Frontend memanggil properti `s.gap_count` dan `s.overlap_count`, padahal database dan endpoint backend [app.py](file:///c:/laragon/www/wilkerstat-checker/app.py) mengirimkan nama `s.gap` dan `s.overlap`. Akibatnya, nilai selalu jatuh ke `0`.

### B. Solusi
Ubah kode di [static/home.js](file:///c:/laragon/www/wilkerstat-checker/static/home.js) menjadi:
```javascript
: mode === 'gap' ? (s.gap || s.gap_count || 0)
: (s.overlap || s.overlap_count || 0);
```
Dengan perbaikan ini, angka riil capaian masalah langsung muncul:
- **liza**: 78.2 gap / 29.0 overlap
- **sholehah**: 100.7 gap / 14.0 overlap
- **saskia**: 104.2 gap / 67.0 overlap

## 2. Analisis Perbedaan Angka QGIS Topology Checker (140 Gap / 33 Overlap) vs WilkerStat Checker (100.7 Gap / 14.0 Overlap)

Perbedaan angka ini disebabkan oleh 3 faktor fundamental:

### A. Atribusi Fraksional (*Fractional Attribution*) Antar-Petugas
- **QGIS**: Menghitung error per geometri secara mandiri. Satu overlap antara Poligon A dan Poligon B dihitung sebagai 1 pelanggaran utuh bagi layer tersebut.
- **WilkerStat Checker**: Menggunakan pembagian beban proporsional ([validate_shape.py](file:///c:/laragon/www/wilkerstat-checker/validate_shape.py#L615-L618)). Jika sebuah poligon `sholehah` overlap dengan poligon milik `liza`, maka masing-masing petugas hanya dibebani **0.5 overlap** ($1 / 2$). Begitu pula celah (gap) yang berbatasan dengan 3 poligon lintas petugas dibagi $1/3$ ($0.333$). Itulah mengapa hasil di WilkerStat Checker berupa pecahan desimal (14.0 dan 100.667).

### B. Filter Luas & Lebar Minimum (*Noise/Sliver Filtering*)
- **QGIS Topology Checker**: Standarnya tidak memiliki filter ambang batas luas minimum. Celah mikro setipis rambut ($0.0001 \text{ m}^2$) akibat perbedaan presisi koordinat float/digitasi tetap dihitung sebagai error gap/overlap.
- **WilkerStat Checker ([config.py](file:///c:/laragon/www/wilkerstat-checker/config.py))**:
  - `OVERLAP_MIN_AREA_M2 = 1.0` $\text{m}^2$: Overlap di bawah $1 \text{ m}^2$ diabaikan (dianggap sliver digitasi).
  - `GAP_MIN_AREA_M2 = 1.0` $\text{m}^2$: Celah di bawah $1 \text{ m}^2$ diabaikan.
  - `GAP_MAX_WIDTH_M = 10.0` meter: Hanya celah sempit antartetangga ($\le 10$ meter) yang dihitung sebagai gap SLS. Area luar terbuka (laut, hutan besar, perbatasan luar) tidak dianggap gap.

### C. Lingkup Evaluasi Data (*Data Scope*)
- Jika file yang dibuka di QGIS hanya layer milik `sholehah` (318 SLS), QGIS mengecek batas terluar poligon tersebut sebagai "gap" dengan dunia luar jika aturan "no gaps" diaktifkan tanpa batas poligon acuan kabupaten.
- WilkerStat Checker mengevaluasi seluruh poligon kabupaten secara utuh (843 SLS dari ketiga petugas) sekaligus di dalam spatial database.
