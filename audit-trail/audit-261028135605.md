# Analisis & Solusi: Masalah Titik Membesar & "(tanpa petugas)" Kosong

## 1. Titik Mengembang Menjadi Bulat Besar di Skala Zoom Jauh ([ga konsisten.png](file:///c:/laragon/www/wilkerstat-checker/ga%20konsisten.png))

### A. Penyebab
Pada [static/map.js](file:///c:/laragon/www/wilkerstat-checker/static/map.js) (baris 318–335) dan [static/home.js](file:///c:/laragon/www/wilkerstat-checker/static/home.js) (baris 438–451):
- Sumber data titik mengaktifkan fitur bawaan clustering MapLibre:
  `cluster: true, clusterRadius: 40`
- Layer cluster `dots-cluster` menggambar lingkaran pembungkus dengan radius besar (14px hingga 26px) saat di-zoom out:
  `'circle-radius': ['step', ['get', 'point_count'], 14, 100, 20, 1000, 26]`
- Inilah yang menyebabkan titik-titik menyatu menjadi gelembung bulat besar yang menutupi peta. Ketika di-zoom dekat, cluster pecah menjadi titik individual berukuran kecil 5px ([kecil.png](file:///c:/laragon/www/wilkerstat-checker/kecil.png)).

### B. Rencana Perbaikan
1. Nonaktifkan clustering (`cluster: false`) pada sumber GeoJSON `dots` di `map.js` dan `home.js`.
2. Hapus layer `dots-cluster` dan `dots-cluster-count`.
3. Tampilkan seluruh titik secara langsung dengan ukuran yang konsisten dan proporsional terhadap zoom menggunakan interpolasi MapLibre:
   ```javascript
   'circle-radius': [
       'interpolate', ['linear'], ['zoom'],
       8, 1.5,
       12, 2.5,
       15, 4,
       18, 5
   ],
   'circle-opacity': 0.85
   ```
   *Keuntungan*: Di skala makro titik tetap tajam seperti pasir/partikel kecil tanpa gelembung besar, dan di skala mikro membesar wajar sesuai kebutuhan inspeksi lapangan.

## 2. Kategori "(tanpa petugas)" Kosong (0 Dalam / 0 Offside)

### A. Penyebab
Pada [validate_dot.py](file:///c:/laragon/www/wilkerstat-checker/validate_dot.py) fungsi `_update_dot_petugas_stats`:
1. Query utama menggunakan:
   ```sql
   WHERE COALESCE(NULLIF(s.petugas, ''), NULLIF(m.petugas, '')) IS NOT NULL
   ```
   Hal ini membuang 23.581 titik yang belum terpetakan ke petugas dari penghitungan `inside_count` dan `offside`.
2. Blok penanganan orphan di bawahnya hanya meng-insert stat `upload_dot`:
   ```python
   conn.execute("INSERT OR REPLACE INTO petugas_stats ... VALUES ('(tanpa petugas)', 'upload_dot', ?)", (orphan["c"],))
   ```
   Stat `dot_inside` dan `offside` tidak pernah dihitung maupun disimpan untuk `(tanpa petugas)`. Akibatnya, frontend membaca nilai 0.

### B. Rencana Perbaikan
Ubah pengelompokan di `_update_dot_petugas_stats` agar menyertakan fallback nama `'(tanpa petugas)'`:
```python
rows = conn.execute("""
    SELECT COALESCE(NULLIF(s.petugas, ''), NULLIF(m.petugas, ''), '(tanpa petugas)') as petugas,
        COUNT(d.id) as total,
        SUM(CASE WHEN d.status='INSIDE'   THEN 1 ELSE 0 END) as inside_count,
        SUM(CASE WHEN d.flag_repair=1      THEN 1 ELSE 0 END) as offside,
        SUM(CASE WHEN d.flag_position=1    THEN 1 ELSE 0 END) as moved
    FROM dot d
    LEFT JOIN master_shape m ON d.idsubsls_origin = m.idsubsls
    LEFT JOIN shape s ON d.idsubsls_origin = s.idsubsls
    GROUP BY COALESCE(NULLIF(s.petugas, ''), NULLIF(m.petugas, ''), '(tanpa petugas)')
""").fetchall()
```
Dengan ini, seluruh 23.581 titik tanpa petugas langsung memiliki angka `inside_count` dan `offside` yang akurat di database dan UI.
