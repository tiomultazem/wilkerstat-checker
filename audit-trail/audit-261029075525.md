## 1. Analisis & Desain: Judul Utama Aplikasi (`h2 centered`)

### A. Kondisi Saat Ini (Kelemahan UX)
- Tulisan nama aplikasi hanya berupa teks kecil berukuran 16px di pojok kiri atas navbar (`<a class="nav-brand">🗺️ wilkerstat checker</a>`).
- Pada layar monitor kerja (1080p ke atas), identitas aplikasi tenggelam dan terlihat seperti template default kecil.
- Halaman utama (`home.html`) langsung memuat peta dan strip progres tanpa adanya tajuk visual yang menegaskan nama sistem.

### B. Solusi Desain
Menyediakan judul aplikasi yang proporsional, tegas, dan berada di tengah (`h2 centered`).

Terdapat dua opsi penempatan arsitektural:
1. **Opsi A (Navbar Center-Aligned)**:
   - Navbar dibagi menjadi grid 3 kolom:
     - Kiri: Logo mini + Indikator Background Worker.
     - Tengah: `<h2 class="nav-title-center">🗺️ WilkerStat Checker</h2>` (Centered, font-size 20–22px, letter-spacing tegas, warna putih kontras).
     - Kanan: Tautan navigasi (`Home`, `Upload`, `Masalah`, `Riwayat`).
   - *Keunggulan*: Tidak memakan ruang vertikal layar, peta di halaman `home` tetap luas (fullscreen).
2. **Opsi B (Page Header Banner Terpisah)**:
   - Diletakkan di atas container konten atau langsung di bawah navbar sebagai banner judul tersendiri dengan `<h2>` besar centered (font-size 26px).
   - *Keunggulan*: Sangat besar dan mencolok.
   - *Kelemahan*: Mengurangi area pandang vertikal workspace peta GIS di halaman beranda.

**Rekomendasi Terbaik**: Opsi A dengan styling navbar yang diperlebar sedikit (tinggi 58px) dan tipografi `h2` terpusat yang solid dan elegan.

## 2. Analisis & Desain: Filter Live Halaman Masalah (`issues.html` & `issues.js`)

### A. Kondisi Saat Ini (Kelemahan UX)
Pada [static/issues.js](file:///c:/laragon/www/wilkerstat-checker/static/issues.js):
- Dropdown `filterType` (Jenis Masalah) dan `filterPetugas` (Petugas) tidak memiliki event listener `change`. Pengguna yang mengubah pilihan dropdown tidak melihat perubahan apa pun.
- Input pencarian `searchInput` hanya bereaksi saat tombol `btnSearch` ("Cari") diklik atau tombol Enter ditekan.
- Alur ini kaku, lambat (*high friction*), dan terasa ketinggalan zaman (*outdated*).

### B. Solusi Desain Filter Reaktif (Live Filtering)
Mengubah seluruh kontrol filter menjadi reaktif seketika:

1. **Dropdown Filter (`filterType` & `filterPetugas`)**:
   - Diberikan event listener `change`.
   - Begitu opsi diubah (misal memilih `Multipart` atau nama petugas tertentu), data langsung diambil ulang dari API dan tabel diperbarui otomatis tanpa klik tombol.
2. **Input Teks (`searchInput`)**:
   - Diberikan event listener `input` dengan mekanisme **Debounce (250ms)**.
   - Karena data `issues` untuk jenis/petugas terpilih sudah di-*cache* dalam memori variabel `allIssues`, pencarian teks (ID SubSLS / Assignment ID / detail pesan) dilakukan secara instan di sisi klien (*client-side filtering*) tanpa *overhead* request jaringan baru.
   - Hasil pencarian muncul seketika saat pengguna mengetik karakter per karakter.
3. **Penyederhanaan Toolbar (Eliminasi Tombol 'Cari')**:
   - Tombol `<button id="btnSearch">Cari</button>` dihapus dari antarmuka karena fungsinya sudah sepenuhnya otomatis.
   - Tombol `<button id="btnReset">Reset</button>` dipertahankan sebagai tombol *quick clear* untuk mengembalikan semua filter ke posisi awal (*clear all*).
